## Щоденник розробника


## Юніт 1: Персонаж і рух
У цьому юніті я створила основну сцену MainScene та налаштувала підлогу з тайлів за допомогою Tilemap. Для плиток було виставлено PPU = 64 та Order in Layer = -10, щоб підлога відображалася коректно і не перекривала персонажа. Також я створила та підключила скрипт PlayerController з використанням Input System. Персонаж плавно рухається у чотирьох напрямках за допомогою стрілочок та клавіш WASD. Для незалежності швидкості від кадрової частоти (FPS) було використано Time.deltaTime.


## Юніт 2: оточення і фізика
**Що зроблено:** 
Створено та налаштовано ігровий рівень за допомогою Tilemap. Налаштовано фізику руху персонажа (PlayerCharacter) через Rigidbody2D та Input System, застосовано фізичний матеріал NoFriction (Friction = 0) для усунення тертя. Виправлено взаємодію з колайдерами води та усунуто тремтіння персонажа біля стін.

**Що не вийшло або забрало найбільше часу:** 
Найбільше часу пішло на вирішення проблеми із застряганням і липненням персонажа до межі водойми під час руху під кутом. Збереження змін у префабі PlayerCharacter та налаштування Composite Collider 2D вимагали декількох спроб перевірки.

**Що зрозумів про FixedUpdate і колайдери:** 
Зрозумів, що фізичне переміщення об'єктів за допомогою Rigidbody2D.MovePosition потрібно виконувати строго у FixedUpdate з використанням Time.deltaTime для стабільності. Також зрозумів, що прямокутні кути Box Collider 2D можуть зачіплятися за стики тайлів, тому використання Capsule Collider 2D (або заокруглення кутів) та відсутність тертя є критичними для плавного ковзання.

**Що в рівні вийшло не так, як у фізичному паспорті, і чому:** 
Загальне розміщення елементів відповідає плану, проте розміри колайдера персонажа та налаштування Composite Collider 2D для Tilemap довелося коригувати «на ходу», щоб уникнути мікро-застрягань на стиках сітки.

**Що робитиму далі:** 
Реалізацію механіки шкоди та лікування робота, створення лічильника здоров'я


## Юніт 3: система здоров'я
### 09.10.2026 — Юніт 3: система здоров'я

**Що зроблено:**
- Реалізовано базову систему здоров'я для гравця у `PlayerController.cs` (функція `ChangeHealth` з обмеженням діапазону від 0 до `maxHealth` через `Mathf.Clamp`).
- Додано можливість підбору аптечки (`HealthCollectible.cs`), яка додає +1 до здоров'я та зникає.
- Створено властивість `health { get { return currentHealth; } }`, завдяки якій аптечка підбирається лише тоді, коли здоров'я менше за максимальне.
- Створено небезпечну зону (`DamageZone.cs`), що завдає шкоди через `OnTriggerStay2D`.
- Налаштовано режим `Never Sleep` у `Rigidbody 2D` персонажа та систему затримки невразливості (`timeInvincible`), щоб шкода завдавалася з паузами.
- Виконано завдання «More things to try»: реалізовано варіант сильнішої аптечки з можливістю налаштування кількості лікування в Inspector та створено зону повільного лікування.

**Що не вийшло або забрало найбільше часу:**
- Спочатку виникла плутанина з префабом `DamageZone`, тому довелося створювати його з нуля з додаванням `Box Collider 2D` у режимі `Is Trigger`.
- Найбільше часу пішло на розуміння того, чому за замовчуванням здоров'я в зоні шкоди зникає за частку секунди — розібралася з логікою роботи `OnTriggerStay2D` та відліком затримки невразливості у `Update()`.

**Що зрозумів про тригери, public і private:**
- **Тригери (`Is Trigger`):** це колайдери, які не створюють фізичної перешкоди (гравець проходить крізь них), але викликають події в коді (`OnTriggerEnter2D`, `OnTriggerStay2D`), що ідеально підходить для збору предметів та зон шкоди.
- **`public` та `private`:** `public` поля видно в Inspector Unity й до них мають доступ інші скрипти; `private` приховує змінні від зовнішніх змін. Використання властивості `get` дозволяє безпечно читати `private` змінну з інших скриптів без можливості довільно її переписати.

**Яке значення Time Invincible обрав і для якого гравця:**
- Обрала значення **2.0 секунди**. Це дає гравцеві достатньо часу, щоб зреагувати та вибігти з зони шкоди, але робить небезпечні ділянки відчутними. Це значення чудово підходить для звичайного (casual) гравця.

**Що робитиму далі:**
- Перейду до Юніта 4

### 23.10.2026 — Юніт 4: вороги і снаряди

**Що зроблено:** 
Налаштовано патрулювання ворога та механіку шкоди при зіткненні з гравцем. Створено та налаштовано снаряд (монету) з використанням `linearVelocity` для стабільного польоту. Додано анімацію полагодженого ворога `EnemyFixed` і налаштовано тригер `Fixed` в Animator. Скрипт ворога оновлено: при влучанні снаряда вимикається фізика (`simulated = false`) та запускається анімація відремонтованого стану.

**Що не вийшло або забрало найбільше часу:** 
Найбільше часу пішло на усунення самовільного зіткнення між гравцем та снарядом під час спавну, а також на коректну прив'язку анімаційного кліпу `EnemyFixed` до стану у вікні Animator, щоб анімація правильно зациклювалася й відтворювалася.

**Що зрозумів про Animator, шари й Awake:** 
Зрозумів, як працюють тригери (Triggers) в Animator та чому важливо вимикати `Has Exit Time` для миттєвої зміни станів. Зрозумів важливість налаштування `Layer Collision Matrix` для ігнорування колізій між певними об'єктами. Також закріпив роль `Awake()` для швидкої ініціалізації компонентів на початку існування об'єкта.

**Які Speed і Change Time обрав і для якого гравця:** 
Обрав `Speed = 3.0` та `Change Time = 2.0` секунди. Ці значення підходять для нашого основного гравця, оскільки створюють передбачуваний ритм патрулювання ворога та дають достатньо часу для маневрів і прицілювання.

**Що робить мій снаряд з ворогом і як це пасує до моєї рамки:** 
Снаряд (монета) «лагодить» робота: при влучанні ворог зупиняється, перестає наносити шкоду та змінює вигляд на відремонтованого робота з сяючою лампочкою. Це повністю відповідає загальній концепції гри про дружній ремонт та відновлення механізмів без їх знищення.
